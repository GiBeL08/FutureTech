# FutureTech AI: подробное описание проекта

## 1. Общая идея проекта

FutureTech AI - это fullstack-приложение, посвященное технологиям, искусственному интеллекту, новостям, блогам, подкастам и пользовательскому контенту.

Проект состоит из двух основных частей:

- `frontend` - пользовательский интерфейс на Next.js, React и TypeScript.
- `backend-nest` - серверная часть на NestJS, Prisma и PostgreSQL.

Главная идея проекта: создать современный информационный сайт, где пользователь может читать материалы, смотреть новости, изучать ресурсы, подписываться на рассылку, отправлять сообщения через контактную форму, регистрироваться, создавать посты, лайкать и комментировать. Также в проекте есть отдельная админ-панель для управления пользователями, постами, новостями, блогами, сообщениями и настройками сайта.

Backend находится в папке `backend-nest`.

Используемые технологии:

## 3. Как работает проект

Проект работает по классической fullstack-архитектуре.

Пользователь открывает сайт, который написан на Next.js. Когда странице нужны данные, frontend отправляет запрос на backend API. Backend принимает запрос, обращается к базе данных через Prisma и возвращает результат в формате JSON.

Пример:

1. Пользователь открывает страницу новостей.
2. Frontend вызывает функцию получения новостей.
3. Выполняется запрос на endpoint `/api/news`.
4. Backend принимает запрос в `NewsController`.
5. `NewsService` получает данные из PostgreSQL через Prisma.
6. Данные возвращаются на frontend и отображаются на странице.

Все основные backend-маршруты имеют префикс `/api`, потому что в `main.ts` используется:

```ts
app.setGlobalPrefix('api');
```

## 5. База данных

Схема базы данных находится в файле:

```text
backend-nest/prisma/schema.prisma
```

В проекте используется PostgreSQL. Prisma описывает модели базы данных и позволяет работать с таблицами через TypeScript-код.

Основные модели:

- `User` - пользователи.
- `Post` - пользовательские посты.
- `Comment` - комментарии к постам.
- `Like` - лайки постов.
- `BlogPost` - блоговые статьи.
- `NewsArticle` - новости.
- `Video` - видео.
- `PodcastShow` - шоу подкастов.
- `PodcastEpisode` - выпуски подкастов.
- `Resource` - ресурсы.
- `ResourceHighlight` - выделенные ресурсы.
- `Testimonial` - отзывы.
- `Faq` - вопросы и ответы.
- `SimilarNewsItem` - похожие новости.
- `ContactMessage` - сообщения из формы контактов.
- `NewsletterSubscriber` - подписчики рассылки.
- `SiteStat` - статистика сайта.

Самые важные связи:

- Один пользователь может иметь много постов.
- Один пользователь может иметь много комментариев.
- Один пользователь может ставить лайки.
- Один пост может иметь много комментариев.
- Один пост может иметь много лайков.

В модели `Like` есть уникальное ограничение:

```prisma
@@unique([authorId, postId])
```

Это значит, что один пользователь не может поставить несколько лайков на один и тот же пост.

## 6. Авторизация

Авторизация реализована через JWT.

Основные файлы:

```text
backend-nest/src/auth/auth.service.ts
backend-nest/src/auth/auth.controller.ts
backend-nest/src/auth/jwt.strategy.ts
```

### Регистрация

При регистрации:

1. Пользователь отправляет имя, email и пароль.
2. Backend проверяет, существует ли пользователь с таким email.
3. Пароль хешируется через `bcryptjs`.
4. Пользователь создается в базе данных.
5. Backend возвращает JWT-токен и данные пользователя.

Пароль не хранится в базе в открытом виде. В базе хранится только хеш.

### Вход

При входе:

1. Пользователь отправляет email и пароль.
2. Backend ищет пользователя по email.
3. Сравнивает введенный пароль с хешем в базе.
4. Если данные верные, backend возвращает JWT-токен.

Frontend сохраняет токен и данные пользователя в `localStorage`.

## 7. Роли пользователей

В модели `User` есть поле:

```prisma
role String @default("user")
```

По умолчанию пользователь получает роль `user`.

Администратор имеет роль `admin`.

Для защиты админских маршрутов используется `AdminGuard`:

```text
backend-nest/src/common/guards/admin.guard.ts
```

Он проверяет:

- есть ли `Authorization: Bearer ...`;
- валиден ли JWT-токен;
- равна ли роль пользователя `admin`.

Если роль не `admin`, доступ запрещается.

## 8. Пользовательские посты

Посты реализованы в:

```text
backend-nest/src/posts/posts.controller.ts
backend-nest/src/posts/posts.service.ts
```

Основные возможности:

- получить все посты;
- получить один пост;
- создать пост;
- удалить пост;
- получить комментарии;
- добавить комментарий;
- поставить или убрать лайк;
- увеличить счетчик репостов.

Важная логика удаления:

- Обычный пользователь может удалить только свой пост.
- Администратор может удалить любой пост.

Лайки работают как переключатель. Если пользователь уже лайкнул пост, повторный запрос убирает лайк. Если лайка еще нет, он создается.

## 16. Валидация и обработка ошибок

Для проверки входящих данных используется `class-validator`.

Например, при регистрации:

- email должен быть email;
- пароль должен быть минимум 6 символов;
- имя обязательно.

Глобальная валидация включена в `main.ts`:

```ts
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    transform: true,
  }),
);
```

`whitelist: true` означает, что лишние поля из запроса будут удаляться.

Также есть общий фильтр ошибок:

```text
backend-nest/src/common/filters/http-exception.filter.ts
```

Он приводит ошибки NestJS к более простому JSON-ответу.

## 19. Возможные вопросы на защите

### Почему выбран Next.js?

Next.js удобен для создания современных React-приложений. Он поддерживает маршрутизацию, серверный рендеринг, работу с API-запросами, оптимизацию страниц и хорошую структуру проекта.

### Почему выбран NestJS?

NestJS дает строгую архитектуру backend-приложения. Код разделяется на модули, контроллеры и сервисы. Это делает проект более понятным, масштабируемым и удобным для поддержки.

### Почему используется Prisma?

Prisma упрощает работу с базой данных. Вместо ручного написания SQL-запросов можно использовать типизированный TypeScript API. Также Prisma описывает структуру базы в одном файле `schema.prisma`.

### Как защищены пароли?

Пароли не хранятся в открытом виде. Перед сохранением пароль хешируется с помощью `bcryptjs`. При входе введенный пароль сравнивается с хешем.

### Как работает авторизация?

После входа или регистрации backend выдает JWT-токен. Frontend сохраняет его в `localStorage` и отправляет в заголовке `Authorization: Bearer token` при запросах к защищенным endpoints.

### Как работает админка?

У пользователя есть роль. Если роль равна `admin`, он может открыть админ-панель. Backend дополнительно проверяет роль через `AdminGuard`, поэтому просто открыть страницу недостаточно: защищены сами API-маршруты.

### Как работает лайк?

В базе есть таблица `Like`, где хранится связь пользователя и поста. Если лайк уже есть, повторный запрос удаляет его. Если лайка нет, он создается.

## 20. Нюансы и зоны для доработки

В проекте есть несколько мест, которые можно улучшить:

- На главной странице один запрос идет к `blog`, а backend-маршрут называется `blogs`.
- На frontend есть функция `getNewsBySlug`, которая ожидает маршрут `/news/:id`, но backend сейчас реализует только `/news`.
- На frontend есть функция `getResourceHighlights`, которая ожидает `/resources/highlights`, но backend возвращает highlights внутри `/resources`.
- Часть комментариев в коде отображается с неправильной кодировкой. Логику это не ломает, но код можно привести к нормальному виду.
- Можно унифицировать формат API-ответов, чтобы везде было либо `{ data }`, либо `{ success, data }`.

Эти пункты не мешают общей архитектуре, но их можно назвать как направления дальнейшего улучшения проекта.

Мой проект называется FutureTech AI. Это fullstack-сайт о технологиях и искусственном интеллекте. Он состоит из frontend-части на Next.js и backend-части на NestJS. Для базы данных используется PostgreSQL, а взаимодействие с базой реализовано через Prisma ORM.
